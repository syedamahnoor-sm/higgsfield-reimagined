## 1. Architecture

**Stack:** Next.js (App Router), TypeScript, Tailwind, Zustand, Framer Motion and lucide icons, deployed on Vercel.

- **Why Next.js rather than plain Vite:** it gives one server route (`/api/generate`) that keeps an API key secret if we do real generation. Everything else runs in the browser. Vercel deploys on every push, so a public URL exists from hour one.
- **No backend database and no login.** The Library is stored in the browser: settings and metadata in localStorage, uploaded reference images in IndexedDB. This is the honest choice for a build without login, and the Library's empty state should say "saved on this device".
- **One generation interface** (`generate(settings) → Job`) with two engines behind it: a simulated engine and a real one. The UI never knows which one ran, so switching between them or falling back on errors is easy.

## 2. Routes and components

| Route | Purpose |
|---|---|
| `/` | Redirects to `/create/image` |
| `/create/image` | Image workspace |
| `/create/video` | Video workspace (same layout, different controls) |
| `/explore` | Gallery. `?item=id` opens a detail modal, not a separate page |
| `/library` | `?filter=all\|images\|videos\|favorites`. `?item=id` opens the viewer |

**Shell:** a slim left rail (about 72px) with Create, Explore and Library. A rail keeps vertical space for media, which a top bar would take. On mobile it becomes a bottom tab bar.

**Create workspace:**
- `ModeSwitch`: an Image / Video toggle that sits inside the composer, not in the main navigation.
- `Canvas`:
  - `InspirationCanvas` before the first generation.
  - `GenerationStage` while generating: placeholders at the chosen aspect ratio, a progress state, and the prompt echoed back.
  - `ResultViewer` after generation: the result is large, with `ResultActions` on it (Download, Favorite, Remix, Use as reference, Animate).
- `SessionFilmstrip`: a vertical strip on the right with this session's generations. Click one to bring it back to the canvas.
- `Composer`: docked at the bottom of the canvas and floating over it.
  - The prompt input is the largest element.
  - Below it sits one row of chips: `ReferenceSlot`, `IntentPicker`, `AspectPicker`, `CountPicker`, and in Video mode `MotionPresetPicker` and `DurationPicker`.
  - A `Model` button opens the advanced model popover.
  - `GenerateButton` sits on the right. Ctrl/⌘+Enter also generates.

**Shared components:**
- `MediaGrid`: a masonry grid used by both Explore and Library.
- `MediaCard`: videos play on hover; actions appear on hover or keyboard focus.
- `MediaViewer` modal: shows the prompt, the settings as chips, and the actions.
- `Toast` with undo.
- `EmptyState`.

## 3. State and data model

```ts
type Mode = 'image' | 'video'
type Intent = 'auto' | 'photoreal' | 'design' | 'fast'
type MotionPreset = 'push-in' | 'orbit' | 'pan' | 'drift' | 'handheld' | 'zoom-out'

interface GenSettings {
  mode: Mode; prompt: string; intent: Intent; modelId?: string  // override from the advanced popover
  aspect: '1:1'|'4:5'|'3:4'|'16:9'|'9:16'; count: 1|2|4
  reference?: { assetId?: string; url: string }                 // a Library asset or an upload
  motion?: MotionPreset; duration?: 5|10
}
interface Asset {          // everything in the Library
  id; kind: Mode; url; posterUrl?; width; height
  settings: GenSettings; resolvedModel: string                  // what "Auto" actually picked
  parentId?: string        // where it came from (Explore item or another asset)
  favorite: boolean; createdAt; jobId
}
interface Job { id; settings; status: 'queued'|'running'|'done'|'failed'; progress; assetIds: string[]; error? }
interface ExploreItem { id; kind; url; posterUrl?; title; settings: GenSettings; tags: string[] }  // a static JSON file
```

**Store slices:**
- `drafts: Record<Mode, GenSettings>`: one draft per mode, so switching tabs never loses a prompt.
- `jobs`
- `assets`
- `session`: the IDs shown in the filmstrip.

**Actions that connect the screens:**
- `remix(settings, parentId)`: copies the settings into the matching draft, navigates to Create, and shows a toast with Undo, since the old draft is replaced.
- `useAsReference(asset)`
- `animate(asset)`: sets the video draft's reference to the asset and navigates to Create.
- `toggleFavorite`
- `download`

**Jobs live in the global store, not in a component.** Navigating away mid-generation must not lose the result. The Library shows those items as pending cards.

## 4. Generation: simulated or real

My recommendation is a hybrid, with a firm timebox on the real part.

- **Image, real.** One provider: fal.ai, which hosts several models behind one API. The intents map to real models:
  - Fast → FLUX schnell
  - Auto → FLUX dev
  - Photoreal → FLUX 1.1 pro
  - Design & Text → Ideogram or Recraft

  That makes the intents meaningful and keeps the advanced popover honest (about 4 real models, not a fake catalogue). Cost is fractions of a cent to a few cents per image. The server route gets:
  - a rate limit per IP
  - a daily cap
  - a timeout that falls back to the simulated engine.

  **Timebox: 2 hours.** If it isn't solid by then, we ship simulated only.
- **Image, simulated (default fallback).** A curated set of about 40 images tagged by subject and style. The engine matches the prompt's keywords to the tags, runs a believable 4–8 second progress phase, and returns the best matches. The weakness is that results don't truly follow the prompt, which judges will notice.
- **Video: no real API.** Real video models take 1–3 minutes and cost real money per clip, and that is where integration work would eat the project. Instead:
  - **Image → video (Animate):** the motion preset is drawn in the browser on the user's actual image (push-in, orbit-style parallax, pan, handheld shake). The output really reflects their input and their preset. It plays as a looping video; recording a downloadable .webm via MediaRecorder is a stretch goal.
  - **Text → video:** with real image generation on, make a first frame from the prompt, then apply the motion. The result matches the prompt. With simulated generation, pick the closest curated clip.
  - Tradeoff: this is camera motion over a still, not real video synthesis. The README should say so plainly.
- **Seed content:** make the Explore images with the same real model, so their prompts are accurate and Remix reproduces something similar. Videos come from Pexels (free licence) or from the motion renderer.

## 7. What I'd cut or change

- **Text-only video as a headline feature.** It's the least believable path. Make Animate (image → video) the main video story; text → video goes through image first.
- **Design & Text** only works with a real text-capable model. If we stay simulated, drop it to three intents rather than fake it.
- **Advanced model selector:** keep it, but small. It shows what Auto picked ("Auto → FLUX dev") and allows an override among the 3–4 real models. No catalogue.
- **Explore detail as its own page:** use a modal over the grid instead.
- **Mobile:** fully working, but not pixel-polished. Composer as a bottom sheet, single-column grids.
- **Also out of scope:** inpainting, upscaling, editing, prompt enhancement with an LLM, any sharing or social features.

## 8. UX issues I think the plan misses

1. **Where previous results go.** If each Generate replaces the canvas, iterating destroys the history. That's why the session filmstrip is in the plan, and generating 2 or 4 variations per run lets the user compare.
2. **"Remix" is ambiguous.** It could mean "reuse the prompt and settings" or "use this image as input". Higgsfield keeps those separate, and we should too: **Remix** reuses settings, **Use as reference** reuses the image, and **Animate** goes to video with the image as reference.
3. **Remix replaces a draft.** The user can lose a prompt they were writing, so it needs an Undo toast.
4. **Jobs must survive navigation.** As described in section 3, and failures need visible, recoverable states: retry, and content-moderation errors.
5. **Time to the first result.** Judges will open the URL cold. Inspiration tiles on the empty canvas should have a "Try this" that fills the prompt in one click, so the core loop is reachable in two clicks.
6. **An empty Library on first visit.** Don't seed it with fake "my generations". Show an empty state that points to Explore and Create.
7. **Auto should show its choice.** Displaying what it picked builds trust and teaches the model layer gradually instead of hiding it.
8. **Being upfront about what's simulated.** Put a short "how generation works" section in the README, and a subtle engine label in the advanced popover. It's better product judgment than letting a judge discover it.
9. **The reference image's aspect ratio vs the chosen one.** Default the aspect ratio to the reference's when one is attached.
